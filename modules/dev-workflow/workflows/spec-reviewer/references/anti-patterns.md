# Credit-Killing Patterns Reference

_Last updated: 2026-07-30 · v2.0.0_

50 patterns that waste tokens, trigger re-prompts, and burn API credits. Organized by failure category, from simple prompt mistakes to complex agentic runtime failures.

**When to use this file:**

- You are reviewing or debugging a prompt that is underperforming.
- A user pastes a bad prompt and asks you to fix it — diagnose it against these patterns by number.
- You are building a new prompt and want to pre-check it before sending.

**Severity key:**

- 🔴 Critical (can destroy data, loop infinitely, or burn significant credits)
- 🟡 Warning (causes re-prompts, hallucination, or poor output)
- 🟢 Minor (suboptimal but functional)

## 1 · Task Patterns

Failures in defining what the AI should actually do. These cause the model to guess your intent and produce output you did not ask for.

| #   | Sev | Pattern                        | Bad Example                                                               | Why It Costs You                                                                                               | Fixed                                                                                                                                                                        |
| --- | --- | ------------------------------ | ------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 🟡  | **Vague task verb**            | "help me with my code"                                                    | Model produces a generic tutorial instead of the specific action you needed. You re-prompt.                    | "Refactor `getUserData()` to use async/await and handle null returns"                                                                                                        |
| 2   | 🟡  | **Two tasks in one prompt**    | "explain AND rewrite this function"                                       | Model merges both, does neither well. Explanation is shallow, rewrite misses context from the explanation.     | Split into two prompts: explain first, rewrite second                                                                                                                        |
| 3   | 🟡  | **No success criteria**        | "make it better"                                                          | No way to know when to stop. Model guesses what "better" means and often guesses wrong. You iterate 3-4 times. | "Done when the function passes existing unit tests and handles null input without throwing"                                                                                  |
| 4   | 🔴  | **Over-permissive agent**      | "do whatever it takes"                                                    | Agent deletes files, installs random dependencies, or rewrites unrelated code. Blast radius is unlimited.      | "Allowed: edit files in `src/auth/`. Forbidden: delete files, modify `package.json`, touch `.env`"                                                                           |
| 5   | 🟢  | **Emotional task description** | "it's totally broken, fix everything"                                     | "Everything" has no scope. Model fixes one thing and declares victory, or touches 20 files.                    | "Throws uncaught TypeError on line 43 when `user` is null"                                                                                                                   |
| 6   | 🟡  | **Build-the-whole-thing**      | "build my entire app"                                                     | Exceeds any model's context and coherence limit. Output is a skeleton that works for nothing.                  | Prompt 1: "Scaffold a Next.js 15 app with these routes: ..." · Prompt 2: "Implement the /dashboard page with ..." · Prompt 3: "Add error handling and loading states to ..." |
| 7   | 🟡  | **Implicit reference**         | "now add the other thing we discussed"                                    | Model has no memory of "the thing." Hallucinates a plausible but wrong feature.                                | Always restate the full task. Never reference "the thing we discussed"                                                                                                       |
| 8   | 🟡  | **Conflicting instructions**   | System prompt says "add documentation" + later says "do NOT add comments" | Model oscillates or picks one arbitrarily. Output is inconsistent across runs.                                 | Audit all instructions for contradictions. One source of truth per rule.                                                                                                     |
| 9   | 🟡  | **Goal without verification**  | "implement the feature"                                                   | No way to confirm it works. You discover the bug 3 prompts later and have to undo.                             | "Done when `npm test` passes and `GET /api/users` returns 200 with the new `role` field"                                                                                     |

## 2 · Context Patterns

Failures in providing the background information the model needs. These cause hallucination, contradictions, and off-target output.

| #   | Sev | Pattern                          | Bad Example                                                             | Why It Costs You                                                                                              | Fixed                                                                                                               |
| --- | --- | -------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 10  | 🟡  | **Assumed prior knowledge**      | "continue where we left off"                                            | Model has no memory between sessions. It invents a plausible "where we left off" that is wrong.               | Include a Memory Block with all prior decisions at the start of every new session                                   |
| 11  | 🟡  | **No project context**           | "write a cover letter"                                                  | Model writes a generic letter for a generic person. You re-prompt with details you should have given upfront. | "PM role at B2B fintech, 2yr SWE experience transitioning to product, shipped 3 features as tech lead"              |
| 12  | 🟡  | **Forgotten stack**              | New prompt contradicts prior tech choice                                | Model picks a different framework than the one you established 5 prompts ago. You lose coherence.             | Always include Memory Block with established stack decisions                                                        |
| 13  | 🟡  | **Hallucination invite**         | "what do experts say about X?"                                          | Model invents citations, fake studies, and non-existent experts.                                              | "Cite only sources you are certain of. If uncertain, say so explicitly rather than guessing."                       |
| 14  | 🟢  | **Undefined audience**           | "write something for users"                                             | Model guesses the reading level, tone, and technical depth. Output mismatches your actual audience.           | "Non-technical B2B buyers, no coding knowledge, decision-maker level"                                               |
| 15  | 🟡  | **No mention of prior failures** | (no context about what was already tried)                               | Model suggests the exact approach you already tried and failed with. You waste a turn.                        | "I already tried X and it didn't work because Y. Do not suggest X."                                                 |
| 16  | 🟡  | **Context dumping**              | Pasting 10,000 lines of code "for context"                              | Model spends most of its attention budget on irrelevant code. Key details get buried. Token cost spikes.      | Scope to the 1-3 files relevant to the task. Use `@file` references or targeted snippets, not full pastes.          |
| 17  | 🟢  | **Stale system prompt**          | System prompt references patterns or model behaviors from 6+ months ago | Instructions optimize for a model version that no longer exists. Output quality degrades silently.            | Version-date your system prompts. Review quarterly. Mark model-specific facts with the model version they apply to. |

## 3 · Format Patterns

Failures in specifying what the output should look like. These cause re-prompts because the answer is right but the shape is wrong.

| #   | Sev | Pattern                                  | Bad Example                                       | Why It Costs You                                                                              | Fixed                                                                                           |
| --- | --- | ---------------------------------------- | ------------------------------------------------- | --------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 18  | 🟡  | **Missing output format**                | "explain this concept"                            | Model picks a format (essay, list, code, table) that does not match what you needed.          | "3 bullet points, each under 20 words, with a one-sentence summary at top"                      |
| 19  | 🟢  | **Implicit length**                      | "write a summary"                                 | Model writes 3 paragraphs when you wanted 3 sentences, or vice versa.                         | "Write a summary in exactly 3 sentences"                                                        |
| 20  | 🟡  | **No role assignment**                   | (no role specified)                               | Model defaults to a generic assistant tone. Output lacks domain-specific depth or vocabulary. | "You are a senior backend engineer specializing in Node.js and PostgreSQL"                      |
| 21  | 🟢  | **Vague aesthetic adjectives**           | "make it look professional"                       | Model interprets "professional" differently every run. Output is inconsistent.                | "Monochrome palette, 16px base font, 24px line height, no decorative elements"                  |
| 22  | 🟢  | **No negative prompts for image AI**     | "a portrait of a woman"                           | Image model adds artifacts, watermarks, extra fingers, or background clutter.                 | Add: "no watermark, no blur, no extra fingers, no distortion, no text overlay"                  |
| 23  | 🟢  | **Prose prompt for Midjourney**          | Full descriptive sentence                         | Midjourney parses comma-separated tokens, not prose. Prose wastes tokens and reduces control. | "subject, style, mood, lighting, composition, --ar 16:9 --v 6"                                  |
| 24  | 🟡  | **No schema for structured output**      | "return the data as JSON"                         | Model invents field names, nests inconsistently, and uses wrong types. You parse and fail.    | Provide the exact JSON schema: `{ "name": string, "email": string, "role": "admin" \| "user" }` |
| 25  | 🟢  | **Prose when structured data is better** | "describe the comparison between options A and B" | Model writes paragraphs. You wanted a scannable comparison.                                   | "Output a markdown table: columns = Option, Pros, Cons, Risk Level, Recommendation"             |

## 4 · Scope Patterns

Failures in bounding what the AI is allowed to touch. These cause agent drift, unintended side effects, and wasted context.

| #   | Sev | Pattern                          | Bad Example                                                     | Why It Costs You                                                                                                | Fixed                                                                                                                                                             |
| --- | --- | -------------------------------- | --------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 26  | 🔴  | **No scope boundary**            | "fix my app"                                                    | Agent edits 15 files when only 1 was broken. Introduces new bugs in code you did not ask it to touch.           | "Fix only the login form validation in `src/auth.js`. Touch nothing else."                                                                                        |
| 27  | 🟡  | **No stack constraints**         | "build a React component"                                       | Model picks its own library versions, CSS framework, and state management. Conflicts with your existing stack.  | "React 18, TypeScript strict, no external libraries, Tailwind only"                                                                                               |
| 28  | 🔴  | **No stop condition for agents** | "build the whole feature"                                       | Agent runs until context is full. No checkpoints, no way to course-correct mid-run. Burns entire credit budget. | "Stop after each step and output: ✅ [what was completed]. Wait for my approval before continuing."                                                               |
| 29  | 🟡  | **No file path for IDE AI**      | "update the login function"                                     | IDE agent finds 3 files with "login" in the name. Edits the wrong one.                                          | "Update `handleLogin()` in `src/pages/Login.tsx` only"                                                                                                            |
| 30  | 🟡  | **Wrong template for tool**      | GPT-style prose prompt used in Cursor                           | Each tool has different instruction-reading behavior. A prompt optimized for ChatGPT underperforms in Cursor.   | Adapt the prompt to the tool: IDE agents need file paths and scope locks. Chat models need role + output format. Reasoning models need clean, short instructions. |
| 31  | 🟡  | **Pasting entire codebase**      | Full repo context every prompt                                  | 98% of tokens are irrelevant. Model attention is diluted. Cost per prompt skyrockets.                           | Scope to only the relevant function and its immediate dependencies                                                                                                |
| 32  | 🔴  | **God agent / monolith prompt**  | One system prompt handles support, billing, coding, and writing | Too many tools and instructions. Model reasoning degrades. Responses become generic.                            | Decompose into specialized agents with limited tool sets and clear handoff triggers                                                                               |
| 33  | 🔴  | **No budget or step cap**        | Agent runs indefinitely until it "figures it out"               | A confused agent can burn hundreds of API calls in a loop without making progress.                              | "Max 15 steps. If not resolved after 15 steps, stop and report what was attempted and what remains."                                                              |

## 5 · Reasoning Patterns

Failures in how the model is asked to think. These cause shallow analysis, hallucinated reasoning, or degraded output on reasoning-native models.

| #   | Sev | Pattern                                    | Bad Example                                       | Why It Costs You                                                                                                        | Fixed                                                                                                         |
| --- | --- | ------------------------------------------ | ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 34  | 🟡  | **No CoT for logic task**                  | "which approach is better?"                       | Model picks one without analysis. No tradeoffs stated, no reasoning visible.                                            | "Think through both approaches step by step. State tradeoffs before recommending."                            |
| 35  | 🔴  | **Adding CoT to reasoning models**         | "think step by step" sent to o3/o4-mini/R1/Qwen3  | Reasoning models think internally. Adding CoT instructions creates interference and measurably degrades output quality. | Remove all reasoning scaffolding. Send clean, short instructions. Let the model reason natively.              |
| 36  | 🟡  | **Expecting inter-session memory**         | "you already know my project"                     | No model has persistent memory across sessions by default. It invents a plausible but wrong project state.              | Always re-provide the Memory Block in every new session                                                       |
| 37  | 🟡  | **Contradicting prior work**               | New prompt ignores earlier architecture decisions | Model builds on a different foundation than what was established. Output conflicts with prior work.                     | Include Memory Block with all established decisions                                                           |
| 38  | 🟡  | **No grounding rule for factual tasks**    | "summarize what experts say about X"              | Model invents plausible-sounding facts and citations. No mechanism to distinguish knowledge from confabulation.         | "Use only information you are highly confident is accurate. If uncertain, state [uncertain] explicitly."      |
| 39  | 🟡  | **No tool-use instruction**                | "calculate the compound interest over 30 years"   | Model does arithmetic in prose and gets it wrong. Rounding errors compound across steps.                                | "Use the code interpreter / calculator tool for all numerical calculations. Do not do math in prose."         |
| 40  | 🟢  | **Asking for certainty on uncertain data** | "what is the exact market size for X?"            | Model produces a confident-sounding number with no basis. You build a plan on a fabrication.                            | "Provide your best estimate with a confidence range. State explicitly when data is unavailable or uncertain." |

## 6 · Agentic Setup Patterns

Failures in configuring an AI agent before it starts running. These cause the agent to drift, break things, or produce work that does not match the intended outcome.

| #   | Sev | Pattern                                | Bad Example                                             | Why It Costs You                                                                                                                                                                | Fixed                                                                                                                                                                       |
| --- | --- | -------------------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 41  | 🟡  | **No starting state**                  | "build me a REST API"                                   | Agent does not know what already exists. May scaffold over existing code or duplicate work.                                                                                     | "Empty Node.js project, Express installed, `src/app.js` exists with a health-check route"                                                                                   |
| 42  | 🟡  | **No target state**                    | "add authentication"                                    | Agent has no definition of "done." It adds a partial auth flow and stops at an arbitrary point.                                                                                 | "`/src/middleware/auth.js` with JWT verify. `POST /login` and `POST /register` in `/src/routes/auth.js`. Done when both routes return 200 with valid tokens."               |
| 43  | 🟡  | **Silent agent**                       | No progress output requested                            | Agent runs for 20 steps with no visibility. You discover it went off-track at step 3 and wasted 17 steps.                                                                       | "After each step output: ✅ [what was completed] and 📋 [what is next]"                                                                                                     |
| 44  | 🔴  | **Unlocked filesystem**                | No file restrictions                                    | Agent edits config files, deletes test fixtures, or modifies `.env` with production credentials.                                                                                | "Only edit files inside `src/`. Do not touch `package.json`, `.env`, or any config file."                                                                                   |
| 45  | 🔴  | **No human review trigger**            | Agent decides everything autonomously                   | Agent deletes files, adds dependencies, or changes the database schema without asking. Changes may be irreversible.                                                             | "Stop and ask before: deleting any file, adding any dependency, or changing the database schema"                                                                            |
| 46  | 🟡  | **Vague first turn on literal models** | "fix the auth bug" with no scope, no files, no criteria | Newer frontier models (Claude Opus 4.7+, GPT-5.x) read prompts literally. They no longer fill implicit context the way earlier models did. Vague prompts produce vague results. | Front-load intent, file scope, constraints, and acceptance criteria in the first message. Be explicit about what "fixed" means.                                             |
| 47  | 🟡  | **Context rot on long sessions**       | Keeps correcting in the same session for 60+ turns      | Model attention degrades as context fills. Earlier instructions get lost. Quality drops sharply after ~50% context usage.                                                       | New task = new session. Use context-management commands if your tool supports them (e.g., `/compact`). Delegate file-heavy investigation to subagents or separate sessions. |

## 7 · Loop & Failure Patterns

Failures in how an agent handles errors, retries, and dead ends at runtime. These are the #1 credit-killer in agentic workflows — a single loop can burn hundreds of API calls in minutes.

| #   | Sev | Pattern                           | Bad Example                                                                                        | Why It Costs You                                                                                                    | Fixed                                                                                                                                               |
| --- | --- | --------------------------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 48  | 🔴  | **Retry-without-correction loop** | Agent hits a 404, retries the same API call 50 times                                               | Each retry costs tokens. No correction means no progress. Credits burn linearly with each attempt.                  | "If a tool call fails twice with the same error, stop and report the failure. Do not retry the same action a third time."                           |
| 49  | 🔴  | **Jitter loop**                   | Agent slightly changes parameters each retry (date format, query wording) to evade dedup           | Looks like progress but is not. Each variation fails for the same root cause. Harder to detect than simple retries. | "If the same tool has been called 3+ times in this task with similar inputs, stop and ask for guidance instead of varying the arguments."           |
| 50  | 🔴  | **Handoff ping-pong**             | Agent A → Agent B → fails → back to Agent A → Agent B → ∞                                          | Multi-agent loops are invisible until you check the bill. Two agents can bounce a task forever.                     | "Max 1 handoff per task. If the receiving agent cannot resolve it, escalate to the user. Never return a failed task to the sending agent."          |
| 51  | 🟡  | **Silent token drain**            | Agent narrates every thought: "I will now examine the file... I can see that the file contains..." | Every narrated word is billed. An agent that "thinks out loud" can use 3-5x the tokens of one that acts directly.   | "Do not narrate your process. Output only: actions taken, results found, and the final deliverable."                                                |
| 52  | 🔴  | **No circuit breaker**            | No mechanism to stop a failing agent from looping                                                  | Agent enters a bad state and keeps running until the credit budget or context window is exhausted.                  | "Hard limit: 20 tool calls per task. After 3 consecutive failures, stop execution and report what failed and why."                                  |
| 53  | 🟡  | **Tool trust without validation** | Agent treats all MCP/tool results as ground truth                                                  | A tool returns malformed data, stale cache, or an error wrapped in a 200. Agent builds on the bad data.             | "Validate tool output before using it. If output looks malformed, empty, or contradicts known facts, report the discrepancy instead of proceeding." |

## 8 · Multi-Model Patterns

Failures in using multiple models, model routing, or inter-agent communication. These cause wasted spend, inconsistent output, and broken pipelines.

| #   | Sev | Pattern                               | Bad Example                                                | Why It Costs You                                                                                                     | Fixed                                                                                                                                                                            |
| --- | --- | ------------------------------------- | ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 54  | 🟡  | **One prompt for all models**         | Same verbose prompt sent to Claude, GPT, and o3            | Each model has different instruction-reading behavior. A prompt optimized for one actively degrades on another.      | Adapt per model: Claude prefers explicit context and XML tags. GPT prefers dense, short instructions. Reasoning models (o3, R1) need clean instructions with no CoT scaffolding. |
| 55  | 🟡  | **Wrong model for the job**           | Using Opus for a simple classification task                | Frontier models cost 10-30x more than small models. Using them for trivial tasks burns credits without quality gain. | Route simple tasks (classification, extraction, formatting) to small/fast models. Reserve frontier models for complex reasoning, architecture, and creative work.                |
| 56  | 🟡  | **No output contract between agents** | Agent A outputs free-form prose, Agent B tries to parse it | Parsing fails silently or produces garbage. The pipeline looks like it works but the output is corrupt.              | Define a strict schema (JSON with typed fields) for all inter-agent communication. Validate at every handoff boundary.                                                           |
